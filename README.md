# Интернет-магазин доступных цен — проект для Codex

**[Пошаговая инструкция: как скачать, запустить магазин и войти в админку](START_HERE.md)**


## Запуск текущей версии с админкой

Нужен **Node.js 24+**. Из каталога проекта:

```bash
npm ci
npm run admin:create
npm start
```

`admin:create` спросит email и пароль владельца (от 12 символов); пароль не отображается. Учётной записи или пароля по умолчанию нет. Панель доступна по пути `/admin` на сервере приложения; локально сервер слушает `127.0.0.1:8000`. Админку нужно открывать через этот сервер, не через `file://` или Python HTTP server.

Для разработки: `npm run dev`. Настройки можно задать через переменные процесса либо `.env.local` (образец — `.env.example`). `HOST` по умолчанию `127.0.0.1`, `PORT` — `8000`, `SHOP_DATA_DIR` — каталог `var/` проекта. При смене `SHOP_DATA_DIR` используйте то же значение и для сервера, и для команды создания администратора.

В среде без интерактивного терминала можно безопасно задать `SHOP_ADMIN_EMAIL` и `SHOP_ADMIN_PASSWORD` в настройках среды, затем выполнить `npm run admin:create`. Не передавайте пароль аргументом команды и не сохраняйте его в Git. Для смены пароля существующего владельца: `npm run admin:create -- --email <email> --reset`; прежние сессии будут отозваны. Введённые тестовые учётные записи создаются только в временных базах тестов.

### Что работает в первой админке

- Вход и выход по email/паролю, серверные сессии.
- Список товаров с поиском по названию/артикулу и фильтрами статуса/категории.
- Создание и редактирование товаров: название, категория, описание, общие характеристики.
- Подсказки характеристик для категории и произвольные дополнительные поля.
- SKU с произвольными параметрами выбора (цвет, размер, объём, упаковка), собственной ценой, старой ценой и остатком.
- Фотографии товара и отдельных SKU; первая фотография — основная, изображения можно убирать и менять местами через «Сделать основной».
- Выбор товаров чекбоксами, выбор всех найденных и массовые действия: публикация, возврат в черновики и удаление. Операция применяется ко всей выбранной группе или отменяется целиком при ошибке.
- Удаление из списка и карточки с подтверждением. Товар исчезает из витрины и админки; повторный импорт Emall его не восстанавливает. Товар с активным резервом сначала нужно обработать в заказе. История заказов сохраняется.
- Черновик, публикация на витрине и возврат в черновик. Изменения сохраняются только по кнопке; несохранённые правки не публикуются.
- Проверка уникальности артикулов во всём магазине, сочетаний вариантов, цен и остатков; защита от потери параллельных правок через версию записи.

**Проверенный сценарий:** добавить товар с двумя SKU и фотографиями → сохранить черновик → опубликовать → выбрать SKU на витрине → добавить его в корзину → перезапустить сервер → изменить цену → скрыть товар.

### Хранение и границы версии

SQLite (`var/shop.sqlite`) хранит категории, товары, варианты, учётные записи, сессии и сведения о фотографиях. Изображения находятся в `var/uploads/`. И база, и файлы сохраняются между перезапусками; каталог `var/` нужно сохранять на постоянном диске. Он исключён из Git вместе с `.env.local` и `node_modules/`. Для резервной копии остановите процессы записи и скопируйте **весь** каталог данных, включая фотографии.

При первом запуске новая база один раз заполняется 14 согласованными демотоварами из `catalog-data.js`. Следующие запуски не переимпортируют и не перезаписывают изменения. В режиме приложения витрина получает только опубликованные записи из базы через `/catalog-data.js` или `/api/catalog`. Статический исходный файл с демоданными сервер напрямую не выдаёт. Категории в этой версии выбираются из согласованной структуры; редактор дерева категорий, импорт, роли сотрудников ещё не реализованы. Управление заказами описано ниже.

Загружать можно JPEG/PNG/WebP до 8 МБ и 25 мегапикселей: сервер проверяет содержимое, удаляет метаданные и преобразует изображение в WebP до 2000×2000. SVG и анимация не принимаются. До публикации фотографии доступны только после входа; неиспользуемые файлы остаются в каталоге данных, автоматической очистки пока нет.

Пароли хранятся как scrypt-хеши, сессии — как хеши случайных токенов в HttpOnly/SameSite cookies. Для записывающих запросов проверяются Origin и CSRF-токен, попытки входа ограничены. Для внешнего размещения настройте HTTPS через обратный прокси, `NODE_ENV=production` и `SHOP_ORIGIN=https://<домен>` (без завершающего `/`); в этом режиме cookies имеют флаг Secure. Прокси должен сохранять заголовок Host и разрешать загрузки до 8 МБ. Режим разработки разрешает обращения только к localhost; указание внешнего адреса требует `SHOP_ORIGIN`.

Заказы действительно сохраняются на сервере, а доступное количество учитывает резерв. Оплата и доставка согласуются продавцом вручную; платёжный провайдер и службы доставки не подключены.

## Исходный прототип

- `index.html` — актуальный согласованный интерактивный одностраничный HTML/CSS/JS-прототип. Использовать **как исходную точку**, не заменять внезапно другим стилем.
- `preview_desktop.png`, `preview_mobile.png` — изображения согласованного направления.
- Исходные 14 товаров, их иллюстрации и цены демонстрационные. В режиме приложения оформление создаёт настоящий заказ в базе; статический просмотр не отправляет заказы.
- Реализованы база данных, авторизация владельца и первая панель управления товарами. Добавлены серверные заказы и локальный резерв SKU. Платежи, доставка через API и синхронизация внешнего склада ещё не подключены.

## Архитектурные требования

- Одна витрина для всех категорий, одна общая корзина.
- Продукт (Product) отделён от конкретного варианта (ProductVariant / SKU).
- Каждый SKU имеет собственные остатки; учёт доступного количества = физический остаток минус резерв с учётом состояния заказов.
- Категории — иерархия; коллекции/подборки — отдельная сущность; характеристики и фильтры зависят от категории.
- Цены могут отличаться по каналам продаж. Данные о наличии должны исходить из одной авторитетной учётной системы.
- Оформление покупки без обязательной регистрации, но позже необходимо интегрировать реального белорусского платёжного провайдера и службы доставки.
- Безопасность, надёжный резерв остатков, идемпотентность импортируемых заказов и обработка ошибок синхронизации обязательны для реализации, не для демопрототипа.

## Доработанный каталог

- У категорий есть родитель: головные уборы и аксессуары → головные уборы → шапки/повязки; косметика → уход за волосами → шампуни/бальзамы/маски/наборы. Родительский раздел включает товары всех дочерних разделов.
- Поиск учитывает название, описание, артикулы, характеристики и весь путь категории; регистр и различия е/ё не влияют на поиск.
- Диапазон цены и список цветов формируются из товаров выбранного раздела. Пустые поля цены не ограничивают выдачу.
- В выбранном разделе доступны его характеристики; несколько значений одной характеристики работают как «ИЛИ», разные характеристики — как «И». В косметике доступны варианты объёма/комплектации вместо фильтра цвета.
- Цвет/объём и наличие проверяются на одном SKU. Выбранные фильтры можно удалять по одному или сбросить все, сохранив категорию.
- Пагинация: 12, 24 или 48 товаров на странице. Изменение фильтров, сортировки или размера страницы возвращает на первую страницу.
- Состояние хранится в query-параметрах URL: `view`, `cat`, `q`, `collection`, `min`, `max`, `color`, `stock`, `sale`, `attr.<характеристика>`, `sort`, `page`, `size`. Поддерживаются прямые ссылки, перезагрузка и история браузера. Неизвестные параметры фильтров игнорируются, номер страницы ограничивается доступной выдачей.
- На мобильном категории и фильтры раскрываются кнопкой; внутри есть кнопка возврата к товарам. Карточки укрупнены с сохранением доступных действий и структуры данных.

### Запуск и проверка

Витрина сохраняет HTML/CSS/JS и утверждённый стиль без сборки. Для текущих товаров из базы и админки используйте `npm start`. Статическое открытие `index.html` рядом с `catalog-data.js` предназначено только для просмотра исходных демотоваров и не отражает изменений базы.

Браузерные проверки: `node tests/catalog.cjs`. Нужны Node.js, пакет `playwright` и Chromium (`/usr/bin/chromium`, либо путь в `CHROMIUM_PATH`). Проверки подставляют HTML локально, без доступа к внешним сервисам.

Проверяются поиск по категории, иерархия, сочетания характеристик, наличие одного SKU, цены, URL/история, корзина и мобильная ширина 390 px. Для пагинации тест создаёт отдельный набор из 500 товаров в памяти браузера; в саму витрину они не добавляются.

В исходных данных 14 демотоваров. При запуске приложения товары поступают из SQLite. Фильтрация и пагинация пока выполняются в браузере; постраничное API и поиск на сервере будут отдельным этапом.

## Текущие разделы магазина

- **Головные уборы и аксессуары** — головные уборы (шапки и повязки), варежки/перчатки, шарфы.
- **Косметика и бытовая химия** — кремы и уход за волосами (шампуни; существующие демонстрационные бальзамы, маски и наборы сохранены).
- **Хозяйственные товары** — губки и тряпки.
- **Продукты питания** — сладости.

На главной, в мобильном меню и каталоге используется одна структура категорий. Кремы и тряпки пока без товаров: отображается пустой раздел, а не вымышленные позиции. Фильтры для этих разделов появятся по характеристикам добавленных товаров. Существующие идентификаторы категорий, демотовары и SKU сохранены.

## Универсальная карточка товара

Карточка строится из характеристик Product и измерений конкретных SKU, без отдельной разметки для каждой категории. Демо:

- `hat-line`: цвет + размер, цены 50/55 BYN; есть отсутствующие и распроданные сочетания.
- `shampoo-satin`: объём 250/500 мл, цены 34/58 BYN.
- `sponges-dish`: упаковки по 5/10 шт., цены 3,50/6 BYN.
- `sweets-mix`: единственный SKU, без панели выбора; условные вес, состав, аллергены, срок годности и хранение.

У SKU поля `sku`, `name`, `stock`, `options` и необязательные `price`, `old`, `color`. Цена без переопределения берётся из Product. Поле `images` товара и SKU содержит загруженные фотографии. Если их нет, используются демонстрационные SVG или заглушка. Фотографии SKU имеют приоритет перед общими фотографиями товара.

Выбранный SKU сохраняется в параметре `sku` вместе с `product`. Указание неизвестного SKU открывает первый доступный вариант. Недоступные сочетания отключены; распроданный существующий вариант можно посмотреть, но нельзя купить. Количество учитывает уже добавленные позиции.

Корзина хранит `{id, sku, qty}`. Старые записи с `variantIndex` преобразуются при чтении; некорректные записи отбрасываются. Корзина и оформление используют цены конкретных SKU, суммы считаются с точностью до копеек. Корзина сама по себе не резервирует товар: проверка цен и создание резерва выполняются сервером при отправке заказа.

Проверка карточки: `node tests/product.cjs`. Покрыты варианты, цены, ограничения остатков, URL/история, галерея, мобильная ширина, смешанная корзина, расчёт оформления и миграция старой корзины.

## Заказы и резервирование

### Сценарий покупателя

Покупатель без регистрации заполняет имя, телефон, город, адрес (кроме самовывоза), необязательные email/комментарий и подтверждает обработку данных для оформления заказа. Кнопка **«Отправить заказ»** создаёт запись в SQLite и показывает номер. До подтверждения сервера корзина не очищается. При изменении цены или остатка сервер отклоняет отправку, витрина обновляет корзину и предлагает проверить её; введённые контакты остаются в памяти страницы.

Онлайн-оплаты нет. Доставка и способ оплаты согласуются с продавцом. Предварительные тарифы магазина заданы в `server/orders.mjs`: курьер — 8 BYN, почта — 6 BYN, самовывоз — 0 BYN. Перед реальным запуском продавец должен утвердить эти тарифы и заполнить фактические контактные и информационные страницы. Автоматической заявки перевозчику или уведомления по email/телефону эта версия не отправляет.

### Работа продавца

В панели `/admin` откройте **«Заказы»**. Доступны поиск по номеру, имени и телефону, фильтр статуса, страницы по 25 заказов. Карточка содержит контакты, адрес, комментарий, состав и сумму на момент оформления, историю действий. Даты показываются по времени Минска.

Переходы:

- **Новый → Подтверждён**: резерв сохраняется до дальнейшего решения продавца.
- **Новый / Подтверждён → Отменён**: резерв освобождается, физический остаток не меняется.
- **Подтверждён → Отправлен**: товар списывается с физического остатка, резерв снимается в той же транзакции.
- **Подтверждён → Завершён**: выдача при самовывозе, такое же однократное списание.
- **Отправлен → Завершён**: статус меняется без повторного списания.

Отправленные и завершённые заказы не отменяются этой кнопкой: возвраты и отдельный учёт возвратных движений ещё не реализованы. Терминальные заказы нельзя открыть заново. Для новой покупки оформляется новый заказ.

### Остатки и срок резерва

В редакторе SKU поле **«Физический остаток»** означает количество на складе. Рядом показаны резерв и доступное количество. На витрине показывается доступное количество: **физический остаток − резерв**. Нельзя уменьшить физический остаток ниже резерва, удалить зарезервированный SKU или поменять его параметры выбора. Цену и описание можно редактировать: уже созданные заказы сохраняют свои снимки.

Новый заказ ожидает подтверждения 24 часа. `SHOP_RESERVE_HOURS` позволяет изменить срок для новых заказов в пределах 1–168 часов. По истечении срока статус становится **«Резерв истёк»**, товар освобождается. Проверка выполняется раз в минуту запущенным сервером и при чтении каталога/заказов; после остановки и запуска сервера просроченные резервы освобождаются при первом обращении. Подтверждённые заказы автоматически не истекают: продавец должен отправить, завершить или отменить их.

### Надёжность и API

Миграция №2 добавляет таблицы `orders`, `order_items`, `reservations`, `order_events`, `order_limits`. Она применяется автоматически к существующей базе при запуске; существующие товары, фотографии и учётные записи сохраняются. При обновлении проекта сохраняйте весь каталог `var/`.

Создание заказа, проверка доступного количества и резервирование выполняются в одной транзакции `BEGIN IMMEDIATE`. Цены, наличие, сумма и доставка проверяются на сервере. Снимки названий, SKU, параметров и цен не меняются при редактировании товара. Списание при отправке обновляет версию товара, чтобы старое окно редактора не восстановило проданные единицы.

- `POST /api/orders`: создание гостевого заказа. Требуется случайный UUID v4 в заголовке `Idempotency-Key`, JSON, корректный Origin и согласие покупателя. Повтор с тем же ключом/составом возвращает прежний заказ; изменённый запрос с тем же ключом отклоняется. Новых заказов с одного IP — не более 10 в час; повтор не расходует лимит.
- `GET /api/orders/receipt`: восстановление минимального подтверждения с тем же секретным заголовком. В нём нет контактов или адреса; получить карточку по публичному номеру нельзя.
- `GET /api/admin/orders`, `GET /api/admin/orders/:id`, `PUT /api/admin/orders/:id`: список, карточка и смена статуса только после входа. Для изменения нужны CSRF-токен и актуальная версия заказа.

При потере ответа браузер сохраняет только ключ и отпечаток попытки в `sessionStorage`; контакты туда не записываются. Повторная отправка и перезагрузка восстанавливают существующее подтверждение. После успешной покупки новый заказ получает новый ключ. При статическом открытии `index.html` отправка отключена: нужен сервер приложения.

Проверки `npm test` покрывают резервы, идемпотентность, истечение срока, изменения товара, смешанные категории и параллельные соединения SQLite. `npm run test:ui` дополнительно проходит путь покупателя и продавца, повторное нажатие, потерянный ответ, перезагрузку и мобильную ширину 390 px. Тесты используют отдельные временные базы, не создавая заказов в рабочей базе.

## Импорт Emall

Первые **5 настоящих товаров Emall с 13 фотографиями опубликованы на витрине приложения** по указанию владельца. При обычном `npm start` магазин загружает [пакет карточек](data/emall-drafts/manifest.json) и однократно применяет [решение о публикации](data/emall-publication.json). Существующие товары, заказы и пользователи сохраняются. Перезапуск не создаёт дубли и не отменяет последующие ручные правки или снятие товара с витрины.

[Опубликованные товары в каталоге](preview_emall_published.png) · [Карточка покупателя](preview_emall_published_product.png) · [Публикация и проверка](docs/emall-publication.md) · [Что перенесено](docs/emall-drafts.md).

Две исходные обложки шапок оказались недоступны; обложками стали первые рабочие фотографии этих товаров. При [сверке с Emall](docs/emall-review.md) обнаружены изменения двух цен: бежевая шапка — 60 BYN, серо-коричневые варежки — 40 BYN. По справочникам выбранных категорий восстановлены ещё четыре значения характеристик. Шесть значений остаются без подтверждённых названий; подробности и происхождение восстановленных полей — в [review.json](data/emall-drafts/review.json).

Цены и остатки — снимок данных Emall. Остатки при сверке совпали, но учёт резервов маркетплейса по читаемым полям не подтверждён; непрерывной синхронизации между каналами пока нет. Остальной каталог не переносился.

Ручной workflow [«Подготовить 5 черновиков Emall»](.github/workflows/emall-import.yml) получает карточки и фотографии, проверяет пакет в отдельной базе и сохраняет артефакт `emall-drafts`. [Реальный запуск завершился успешно](https://github.com/HannaStarovoy/homeharmony/actions/runs/41797701461); сохранённый пакет полностью совпадает с его результатом. Ключ `EMALL_API_TOKEN` хранится в GitHub Secrets и не входит в пакет, исходники или журналы. Данные карточек и фотографии в этом публичном репозитории доступны посетителям GitHub с разрешения владельца.

**[Проверить только чтение Emall через GitHub — инструкция](docs/emall-github.md).** Этот отдельный workflow выводит безопасную сводку без данных карточек и не создаёт товары. Настраивать облачную среду ChatGPT для запуска через GitHub не требуется.

Проверка чтения из терминала: `node --env-file-if-exists=.env.local scripts/check-emall.mjs --summary`. Сверка прежних пяти карточек: `node scripts/review-emall-drafts.mjs`. Подготовка их обновлённого пакета: `node scripts/prepare-emall-drafts.mjs --saved-ids`. Команды запускаются в процессе с настроенным ключом и не меняют рабочую базу.

[Устройство импорта, ограничения и следующий шаг](docs/emall-import.md). Серверные тесты используют искусственные данные и временные базы. Создание черновиков проверяется отдельно: `node scripts/capture-emall-drafts.cjs`. Публичный каталог, фотографии и повторный запуск с решением о публикации проверяет `node scripts/capture-emall-published.cjs`.

## Массовое управление ассортиментом

В админке отметьте товары флажками и выберите действие. «Сменить категорию» переносит выбранные карточки в указанный раздел. «Изменить цены» меняет цены всех SKU выбранных товаров: положительное значение увеличивает цену, отрицательное уменьшает; можно выбрать сумму в BYN или процент. Перед сохранением показываются прежние и новые цены каждого SKU. Цена после округления должна быть больше нуля. Старая зачёркнутая цена сохраняется только когда она выше новой. Изменения выполняются одной транзакцией с проверкой версии каждой карточки.

Флажок «Требуют проверки» оставляет товары без фотографий, без описания или с незаполненной ценой. Причины указаны рядом с названием. Его можно сочетать с поиском, категорией и статусом.

«Копировать» открывает новую карточку с названием исходного товара и пометкой «копия», фотографиями, описанием и вариантами. У копии новые артикулы, нулевые остатки и статус черновика; связи с Emall и резервы не переносятся. Проверьте поля и нажмите «Сохранить черновик». Исходная карточка не меняется.
