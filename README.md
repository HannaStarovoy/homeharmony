# Интернет-магазин доступных цен — проект для Codex

**[Пошаговая инструкция: как скачать, запустить магазин и войти в админку](START_HERE.md)**


## Запуск текущей версии с админкой

Нужен **Node.js 24+**. Из каталога проекта:

```bash
npm ci
npm run admin:create
npm start
```

`admin:create` спросит email и пароль владельца (от 12 символов); пароль не отображается. Учётной записи или пароля по умолчанию нет. Панель доступна по пути `/admin` на сервере приложения; локально сервер слушает `127.0.0.1:8000`. Админку нужно открывать через этот сервер, не через `file://` или Python HTTP server.

Для разработки: `npm run dev`. Настройки можно задать через переменные процесса либо `.env.local` (образец — `.env.example`). `HOST` по умолчанию `127.0.0.1`, `PORT` — `8000`, `SHOP_DATA_DIR` — каталог `var/` проекта. При смене `SHOP_DATA_DIR` используйте то же значение и для сервера, и для команды создания администратора.

В среде без интерактивного терминала можно безопасно задать `SHOP_ADMIN_EMAIL` и `SHOP_ADMIN_PASSWORD` в настройках среды, затем выполнить `npm run admin:create`. Не передавайте пароль аргументом команды и не сохраняйте его в Git. Для смены пароля существующего владельца: `npm run admin:create -- --email <email> --reset`; прежние сессии будут отозваны. Введённые тестовые учётные записи создаются только в временных базах тестов.

### Что работает в первой админке

- Вход и выход по email/паролю, серверные сессии.
- Список товаров с поиском по названию/артикулу и фильтрами статуса/категории.
- Создание и редактирование товаров: название, категория, описание, общие характеристики.
- Подсказки характеристик для категории и произвольные дополнительные поля.
- SKU с произвольными параметрами выбора (цвет, размер, объём, упаковка), собственной ценой, старой ценой и остатком.
- Фотографии товара и отдельных SKU; первая фотография — основная, изображения можно убирать и менять местами через «Сделать основной».
- Черновик, публикация на витрине и возврат в черновик. Изменения сохраняются только по кнопке; несохранённые правки не публикуются.
- Проверка уникальности артикулов во всём магазине, сочетаний вариантов, цен и остатков; защита от потери параллельных правок через версию записи.

**Проверенный сценарий:** добавить товар с двумя SKU и фотографиями → сохранить черновик → опубликовать → выбрать SKU на витрине → добавить его в корзину → перезапустить сервер → изменить цену → скрыть товар.

### Хранение и границы версии

SQLite (`var/shop.sqlite`) хранит категории, товары, варианты, учётные записи, сессии и сведения о фотографиях. Изображения находятся в `var/uploads/`. И база, и файлы сохраняются между перезапусками; каталог `var/` нужно сохранять на постоянном диске. Он исключён из Git вместе с `.env.local` и `node_modules/`. Для резервной копии остановите процессы записи и скопируйте **весь** каталог данных, включая фотографии.

При первом запуске новая база один раз заполняется 14 согласованными демотоварами из `catalog-data.js`. Следующие запуски не переимпортируют и не перезаписывают изменения. В режиме приложения витрина получает только опубликованные записи из базы через `/catalog-data.js` или `/api/catalog`. Статический исходный файл с демоданными сервер напрямую не выдаёт. Категории в этой версии выбираются из согласованной структуры; редактор дерева категорий, импорт, роли сотрудников и управление заказами ещё не реализованы.

Загружать можно JPEG/PNG/WebP до 8 МБ и 25 мегапикселей: сервер проверяет содержимое, удаляет метаданные и преобразует изображение в WebP до 2000×2000. SVG и анимация не принимаются. До публикации фотографии доступны только после входа; неиспользуемые файлы остаются в каталоге данных, автоматической очистки пока нет.

Пароли хранятся как scrypt-хеши, сессии — как хеши случайных токенов в HttpOnly/SameSite cookies. Для записывающих запросов проверяются Origin и CSRF-токен, попытки входа ограничены. Для внешнего размещения настройте HTTPS через обратный прокси, `NODE_ENV=production` и `SHOP_ORIGIN=https://<домен>` (без завершающего `/`); в этом режиме cookies имеют флаг Secure. Прокси должен сохранять заголовок Host и разрешать загрузки до 8 МБ. Режим разработки разрешает обращения только к localhost; указание внешнего адреса требует `SHOP_ORIGIN`.

Оформление заказа, платежи и резервирование склада остаются демонстрационными. Админка действительно сохраняет товары и остатки, но покупка пока не создаёт серверный заказ и не списывает склад.

### Проверки

```bash
npm test
npm run test:ui
```

Серверные тесты используют временную SQLite-базу; браузерные — Playwright и Chromium (`/usr/bin/chromium` или `CHROMIUM_PATH`). Если Chromium не установлен, установите его штатным способом для своей ОС и задайте путь через `CHROMIUM_PATH`. Проверки не меняют рабочую базу и не используют реальные личные данные. Браузерные снимки тестов сохраняются в `/tmp/`.

## Что уже согласовано

- Единый мультикатегорийный интернет-магазин для Беларуси.
- Ассортимент: головные уборы и аксессуары, косметика и бытовая химия, хозяйственные товары, продукты питания. Около 500 товарных позиций; возможны многочисленные варианты цветов и размеров.
- Позиционирование: **магазин низких цен и широкого ассортимента**, не премиальный бутик и не яркий lifestyle-магазин.
- Утверждённый стиль: светлый фон, синие кнопки и навигационные акценты, хорошо заметные цены и красные скидки, компактные карточки товаров, удобная мобильная версия.
- Функции сайта: главная, каталог, категории, фильтры и сортировка, карточка товара с вариантами, корзина, оформление заказа, информационные страницы.
- Требуется отдельная административная панель для управления товарами, вариантами SKU, остатками, ценами, фотографиями, категориями и заказами.
- Физический склад у продавца (FBS). В перспективе — централизованный учёт и синхронизация сайта с внешними маркетплейсами. Система учёта ещё не выбрана окончательно; обсуждалась 1С и альтернативы. Конкретные маркетплейсы пока не названы.

## Исходный прототип

- `index.html` — актуальный согласованный интерактивный одностраничный HTML/CSS/JS-прототип. Использовать **как исходную точку**, не заменять внезапно другим стилем.
- `preview_desktop.png`, `preview_mobile.png` — изображения согласованного направления.
- Товары, фотографии, цены, доставка и оформление заказа в прототипе демонстрационные.
- Реализованы база данных, авторизация владельца и первая панель управления товарами. Настоящих платежей, серверных заказов и складской синхронизации ещё нет.

## Архитектурные требования

- Одна витрина для всех категорий, одна общая корзина.
- Продукт (Product) отделён от конкретного варианта (ProductVariant / SKU).
- Каждый SKU имеет собственные остатки; учёт доступного количества = физический остаток минус резерв с учётом состояния заказов.
- Категории — иерархия; коллекции/подборки — отдельная сущность; характеристики и фильтры зависят от категории.
- Цены могут отличаться по каналам продаж. Данные о наличии должны исходить из одной авторитетной учётной системы.
- Оформление покупки без обязательной регистрации, но позже необходимо интегрировать реального белорусского платёжного провайдера и службы доставки.
- Безопасность, надёжный резерв остатков, идемпотентность импортируемых заказов и обработка ошибок синхронизации обязательны для реализации, не для демопрототипа.

## Доработанный каталог

- У категорий есть родитель: головные уборы и аксессуары → головные уборы → шапки/повязки; косметика → уход за волосами → шампуни/бальзамы/маски/наборы. Родительский раздел включает товары всех дочерних разделов.
- Поиск учитывает название, описание, артикулы, характеристики и весь путь категории; регистр и различия е/ё не влияют на поиск.
- Диапазон цены и список цветов формируются из товаров выбранного раздела. Пустые поля цены не ограничивают выдачу.
- В выбранном разделе доступны его характеристики; несколько значений одной характеристики работают как «ИЛИ», разные характеристики — как «И». В косметике доступны варианты объёма/комплектации вместо фильтра цвета.
- Цвет/объём и наличие проверяются на одном SKU. Выбранные фильтры можно удалять по одному или сбросить все, сохранив категорию.
- Пагинация: 12, 24 или 48 товаров на странице. Изменение фильтров, сортировки или размера страницы возвращает на первую страницу.
- Состояние хранится в query-параметрах URL: `view`, `cat`, `q`, `collection`, `min`, `max`, `color`, `stock`, `sale`, `attr.<характеристика>`, `sort`, `page`, `size`. Поддерживаются прямые ссылки, перезагрузка и история браузера. Неизвестные параметры фильтров игнорируются, номер страницы ограничивается доступной выдачей.
- На мобильном категории и фильтры раскрываются кнопкой; внутри есть кнопка возврата к товарам. Сетка и оформление товарных карточек сохранены.

### Запуск и проверка

Витрина сохраняет HTML/CSS/JS и утверждённый стиль без сборки. Для текущих товаров из базы и админки используйте `npm start`. Статическое открытие `index.html` рядом с `catalog-data.js` предназначено только для просмотра исходных демотоваров и не отражает изменений базы.

Браузерные проверки: `node tests/catalog.cjs`. Нужны Node.js, пакет `playwright` и Chromium (`/usr/bin/chromium`, либо путь в `CHROMIUM_PATH`). Проверки подставляют HTML локально, без доступа к внешним сервисам.

Проверяются поиск по категории, иерархия, сочетания характеристик, наличие одного SKU, цены, URL/история, корзина и мобильная ширина 390 px. Для пагинации тест создаёт отдельный набор из 500 товаров в памяти браузера; в саму витрину они не добавляются.

В исходных данных 14 демотоваров. При запуске приложения товары поступают из SQLite. Фильтрация и пагинация пока выполняются в браузере; постраничное API и поиск на сервере будут отдельным этапом.

## Текущие разделы магазина

- **Головные уборы и аксессуары** — головные уборы (шапки и повязки), варежки/перчатки, шарфы.
- **Косметика и бытовая химия** — кремы и уход за волосами (шампуни; существующие демонстрационные бальзамы, маски и наборы сохранены).
- **Хозяйственные товары** — губки и тряпки.
- **Продукты питания** — сладости.

На главной, в мобильном меню и каталоге используется одна структура категорий. Кремы и тряпки пока без товаров: отображается пустой раздел, а не вымышленные позиции. Фильтры для этих разделов появятся по характеристикам добавленных товаров. Существующие идентификаторы категорий, демотовары и SKU сохранены.

## Универсальная карточка товара

Карточка строится из характеристик Product и измерений конкретных SKU, без отдельной разметки для каждой категории. Демо:

- `hat-line`: цвет + размер, цены 50/55 BYN; есть отсутствующие и распроданные сочетания.
- `shampoo-satin`: объём 250/500 мл, цены 34/58 BYN.
- `sponges-dish`: упаковки по 5/10 шт., цены 3,50/6 BYN.
- `sweets-mix`: единственный SKU, без панели выбора; условные вес, состав, аллергены, срок годности и хранение.

У SKU поля `sku`, `name`, `stock`, `options` и необязательные `price`, `old`, `color`. Цена без переопределения берётся из Product. Поле `images` товара и SKU содержит загруженные фотографии. Если их нет, используются демонстрационные SVG или заглушка. Фотографии SKU имеют приоритет перед общими фотографиями товара.

Выбранный SKU сохраняется в параметре `sku` вместе с `product`. Указание неизвестного SKU открывает первый доступный вариант. Недоступные сочетания отключены; распроданный существующий вариант можно посмотреть, но нельзя купить. Количество учитывает уже добавленные позиции.

Корзина хранит `{id, sku, qty}`. Старые записи с `variantIndex` преобразуются при чтении; некорректные записи отбрасываются. Корзина и оформление используют цены конкретных SKU, суммы считаются с точностью до копеек. Это локальная демонстрация без серверного резерва.

Проверка карточки: `node tests/product.cjs`. Покрыты варианты, цены, ограничения остатков, URL/история, галерея, мобильная ширина, смешанная корзина, расчёт оформления и миграция старой корзины.
