# Сверка пяти черновиков Emall

Ручной workflow [«Сверить 5 черновиков Emall»](../.github/workflows/emall-review.yml) проверяет только пять ID из сохранённого пакета. Он читает полные карточки, отдельный ответ с ценой и остатком и справочники характеристик. Товары, фотографии и рабочая база при сверке не изменяются.

Ключ берётся из существующего `EMALL_API_TOKEN` в GitHub Secrets. Журнал содержит только количество проверенных карточек, расхождений и нерасшифрованных полей. Артефакт `emall-review` содержит выбранные поля этих пяти товаров; произвольные поля ответа, ключ, заказы и данные покупателей в него не включаются.

## Какие числа сравниваются

- Цена и количество полной карточки сравниваются с сохранённым пакетом.
- `product_stock` из отдельного `GET /open/api/v1/products/short/info/{id}` сравнивается со `stock` полной карточки.
- Основная цена `product_price.price` из того же ответа сравнивается с `prices.price` полной карточки. `red_price` не подставляется вместо основной цены: его роль в этом ответе не объяснена.
- Старая цена, не превышающая текущую, при сравнении нормализуется в ноль, как при импорте. Исходное число остаётся в отчёте. Это исправление скидки не считается изменением цены товара.

Отчёт фиксирует время проверки. Совпадение чисел подтверждает состояние на этот момент, но не включает непрерывную синхронизацию.

## Что известно о резервах

В [официальном разделе Emall об остатках](https://api-sandbox.emall.by/docs#rabota-s-cenami-i-ostatkami-PATCHopen-api-v1-change-products-stock) есть пример ответа с отдельными `warehouse_stock: 7`, `available_stock: 3` и `reserved: 4`. Входной `stock` описан как актуальное количество на складе.

Однако читающие методы возвращают `stock` или `product_stock`, не объясняя их связь с этими тремя значениями. Поэтому равенство чисел в двух читающих ответах ещё не доказывает, что получен физический остаток или количество после резервов. Если API вернёт явные `warehouse_stock`, `available_stock` или `reserved`, отчёт сохранит их отдельно без подстановки отсутствующих значений.

Перед публикацией продавцу нужно сверить доступное количество с кабинетом Emall. Запрос изменения остатков ради диагностики не выполняется. HomeHarmony учитывает собственные резервы отдельно и при повторном импорте сохраняет локальное количество.

## Как повторить проверку

В GitHub откройте **Actions → «Сверить 5 черновиков Emall» → Run workflow**. После успешного запуска отчёт доступен в артефакте `emall-review` в течение семи дней. Он не применяется к магазину автоматически.

Для разработчика: `node scripts/review-emall-drafts.mjs` в процессе с настроенным ключом. Результат сохраняется в `var/emall-review/review.json`. Существующая папка результата не перезаписывается; для новой проверки задайте новый путь через `--output`.
