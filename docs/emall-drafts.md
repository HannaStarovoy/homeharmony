# Первые пять товаров Emall

В [пакете `data/emall-drafts/`](../data/emall-drafts/) сохранены пять настоящих товаров Emall: названия, описания, расшифрованные характеристики, цены, остатки и **13 рабочих фотографий**. После проверки владелец поручил опубликовать эти карточки. Они доступны в каталоге приложения; при обычном `npm start` новая установка также применяет сохранённое [решение о публикации](../data/emall-publication.json).

[Успешный запуск подготовки в GitHub Actions](https://github.com/HannaStarovoy/homeharmony/actions/runs/41797701461). Его пакет побайтово сверен с сохранёнными файлами. В рабочей базе опубликованы пять карточек, общее число опубликованных товаров — 19, включая прежние 14 демонстрационных. Перед публикацией сделана локальная резервная копия SQLite. Пройдены 161 серверный тест и проверка публичных карточек, фотографий и повторного запуска.

Репозиторий `HannaStarovoy/homeharmony` публичный: данные этих пяти карточек и фотографии доступны посетителям GitHub с разрешения владельца. Ключ API, заказы, контакты покупателей и учётные записи в пакет не входят.

## Что требует проверки

В [review.json](../data/emall-drafts/review.json) сохранены предупреждения и происхождение восстановленных полей:

- Шесть значений не удалось расшифровать через справочники: поле `1713` у двух шапок и двух пар варежек, поле `1787` у двух шапок. Они пропущены, их значения не выдуманы.
- Четыре значения восстановлены по тем же ID в справочниках других выбранных категорий: «Ширина, см — 25» у двух шапок и «Назначение — повседневное» у двух пар варежек. Конфликтующие определения не используются, определение своей категории имеет приоритет.
- Бежевая шапка теперь стоит 60 BYN при старой цене 70 BYN; серо-коричневые варежки — 40 BYN при старой цене 60 BYN. Эти изменения подтверждены двумя читающими методами Emall.
- Две исходные обложки шапок возвращали HTML вместо фотографии. Они пропущены; обложками стали первые рабочие фотографии соответствующих товаров. Все сохранённые изображения получены из источника, без заглушек.

## Как устроен перенос

1. Ручной workflow [«Подготовить 5 черновиков Emall»](../.github/workflows/emall-import.yml) читает ровно пять ID из сохранённого пакета через `EMALL_API_TOKEN` в GitHub Secrets. Порядок товаров в каталоге не меняет выборку.
2. Категории сопоставляются с утверждёнными разделами магазина. Для салфеток и варежек соответствия подтверждены по путям категорий Emall и сохранены в `data/emall-category-map.json`. Нераспознанная категория останавливает подготовку.
3. Цены переводятся из копеек в BYN, характеристики расшифровываются по справочникам. Источник обозначен постоянным идентификатором `homeharmony-emall-main`, который не зависит от API-ключа.
4. Фотографии скачиваются отдельно без заголовка авторизации, проверяются и сохраняются в WebP. Пакет содержит локальные фотографии и нормализованные записи, без ключа и исходных URL. Небезопасные адреса останавливают подготовку; недоступное фото пропускается с предупреждением. Если у товара не остаётся ни одного корректного фото, пакет не создаётся.
5. Пакет проверяется в отдельной базе: пять черновиков, отсутствие публикаций, повторное применение без дублей. Workflow сохраняет артефакт `emall-drafts` на семь дней.
6. Проверенный пакет сохраняется в репозитории: `manifest.json`, `review.json` и `media/*.webp`. При обычном `npm start` магазин подхватывает его, сохраняя существующие заказы, пользователей и товары. Затем отдельно применяется однократное решение владельца о публикации этих пяти ID.

Неизменённый пакет при перезапуске не перезаписывает ручные правки и не создаёт дубликаты. Новая версия пакета обновляет данные из источника; ручные фотографии при таком обновлении пока не защищены от замены ссылок на фотографии источника. Повторный импорт сохраняет локальные остатки и статус публикации существующих карточек.

## Проверки и повторная подготовка

`node scripts/capture-emall-drafts.cjs` использует временную базу и проверяет пять разных черновиков, названия, цены в копейках, фотографии в админке, отсутствие карточек и их фотографий в публичном каталоге, а также сохранение ID/SKU после перезапуска. Команда создаёт два снимка выше, не редактируя товары и не публикуя их.

Подготовка обновления прежних пяти карточек из терминала: `node scripts/prepare-emall-drafts.mjs --saved-ids` в процессе с настроенным ключом. Результат записывается в `var/emall-prepared/`; существующий каталог результата не перезаписывается. Рабочая база магазина этой командой не изменяется. Без `--saved-ids` инструмент разработчика выбирает первые пять товаров списка. Облачную среду ChatGPT для запуска через GitHub настраивать не требуется.
