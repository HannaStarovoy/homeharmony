# Первые пять черновиков Emall

В [пакете `data/emall-drafts/`](../data/emall-drafts/) сохранены пять настоящих товаров Emall: названия, описания, расшифрованные характеристики, цены, остатки и **13 рабочих фотографий**. При обычном `npm start` магазин создаёт их в своей SQLite-базе как черновики. Публикация на витрине не выполняется.

[Успешный запуск подготовки в GitHub Actions](https://github.com/HannaStarovoy/homeharmony/actions/runs/41736248900). Его пакет побайтово сверен с сохранёнными файлами. В рабочей базе созданы пять черновиков; число опубликованных товаров осталось прежним — 14. Перед применением сделана локальная резервная копия SQLite. Пройдены 140 серверных тестов и браузерная проверка карточек, фотографий, доступа и повторного запуска.

Репозиторий `HannaStarovoy/homeharmony` публичный: данные этих пяти карточек и фотографии доступны посетителям GitHub с разрешения владельца. Ключ API, заказы, контакты покупателей и учётные записи в пакет не входят.

## Что требует проверки

В [review.json](../data/emall-drafts/review.json) сохранены 13 предупреждений:

- 10 свойств не удалось расшифровать через справочники. Они пропущены, их значения не выдуманы; доступные характеристики перечислены в карточках.
- У бежевой шапки старая цена не превышала текущую. Она сброшена, чтобы не показывать ложную скидку.
- Две исходные обложки шапок возвращали HTML вместо фотографии. Они пропущены; обложками стали первые рабочие фотографии соответствующих товаров. Все сохранённые изображения получены из источника, без заглушек.

Откройте `/admin` → список товаров → фильтр **«Черновики»**. Перед публикацией проверьте категории, фотографии, характеристики, цены и доступное количество. Посмотреть результат без запуска: [список пяти черновиков](../preview_emall_drafts.png), [редактор карточки с фотографиями](../preview_emall_product.png).

## Как устроен перенос

1. Ручной workflow [«Подготовить 5 черновиков Emall»](../.github/workflows/emall-import.yml) читает первые пять товаров через `EMALL_API_TOKEN` в GitHub Secrets.
2. Категории сопоставляются с утверждёнными разделами магазина. Для салфеток и варежек соответствия подтверждены по путям категорий Emall и сохранены в `data/emall-category-map.json`. Нераспознанная категория останавливает подготовку.
3. Цены переводятся из копеек в BYN, характеристики расшифровываются по справочникам. Источник обозначен постоянным идентификатором `homeharmony-emall-main`, который не зависит от API-ключа.
4. Фотографии скачиваются отдельно без заголовка авторизации, проверяются и сохраняются в WebP. Пакет содержит локальные фотографии и нормализованные записи, без ключа и исходных URL. Небезопасные адреса останавливают подготовку; недоступное фото пропускается с предупреждением. Если у товара не остаётся ни одного корректного фото, пакет не создаётся.
5. Пакет проверяется в отдельной базе: пять черновиков, отсутствие публикаций, повторное применение без дублей. Workflow сохраняет артефакт `emall-drafts` на семь дней.
6. Проверенный пакет сохраняется в репозитории: `manifest.json`, `review.json` и `media/*.webp`. При обычном `npm start` магазин подхватывает его, сохраняя существующие заказы, пользователей и товары.

Неизменённый пакет при перезапуске не перезаписывает ручные правки и не создаёт дубликаты. Новая версия пакета обновляет данные из источника; ручные фотографии при таком обновлении пока не защищены от замены ссылок на фотографии источника. Повторный импорт сохраняет локальные остатки и статус публикации существующих карточек.

## Проверки и повторная подготовка

`node scripts/capture-emall-drafts.cjs` использует временную базу и проверяет пять разных черновиков, названия, цены в копейках, фотографии в админке, отсутствие карточек и их фотографий в публичном каталоге, а также сохранение ID/SKU после перезапуска. Команда создаёт два снимка выше, не редактируя товары и не публикуя их.

Подготовка нового пакета из терминала: `node scripts/prepare-emall-drafts.mjs` в процессе с настроенным ключом. Результат записывается в `var/emall-prepared/`; существующий каталог результата не перезаписывается. Рабочая база магазина этой командой не изменяется. Облачную среду ChatGPT для запуска через GitHub настраивать не требуется.
