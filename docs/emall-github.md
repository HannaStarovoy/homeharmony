# Проверка Emall через GitHub

Код магазина и проверка API находятся в репозитории [HannaStarovoy/homeharmony](https://github.com/HannaStarovoy/homeharmony). Для этого способа настройки облачной среды ChatGPT сохранять или публиковать не требуется.

Нужен рабочий API-ключ из кабинета продавца Emall. Можно использовать уже созданный новый ключ. Ключ хранится в GitHub Secrets; значение, введённое в настройках ChatGPT, автоматически в GitHub не переносится.

## 1. Добавить ключ в GitHub

1. Войдите в GitHub и откройте репозиторий [HannaStarovoy/homeharmony](https://github.com/HannaStarovoy/homeharmony).
2. Откройте **Settings → Secrets and variables → Actions**. [Прямая ссылка на этот раздел](https://github.com/HannaStarovoy/homeharmony/settings/secrets/actions).
3. Нажмите **New repository secret**.
4. В поле **Name** введите точно `EMALL_API_TOKEN`.
5. В поле **Secret** вставьте рабочий API-ключ целиком.
6. Нажмите **Add secret**. Если секрет с таким именем уже существует, откройте его редактирование и сохраните актуальное значение.

После сохранения GitHub показывает имя секрета, а его значение скрывает. Ключ не нужно добавлять в файлы репозитория, Issues, комментарии или переписку.

Если вкладка **Settings** недоступна, нужен вход в аккаунт с доступом к настройкам этого репозитория.

## 2. Запустить проверку

1. Откройте вкладку **Actions** репозитория.
2. Слева выберите **Проверить Emall API**. [Прямая ссылка на проверку](https://github.com/HannaStarovoy/homeharmony/actions/workflows/emall-check.yml).
3. Нажмите **Run workflow**, выберите ветку **main** и подтвердите запуск кнопкой **Run workflow**.
4. Откройте появившийся запуск и дождитесь завершения задания **Чтение первых пяти товаров**.

Проверка запускается только вручную. Коммиты, Pull Requests и расписание её не запускают. Из настроек секрета копировать значение в параметры запуска не нужно.

## 3. Прочитать результат

Зелёная отметка означает, что тесты прошли и Emall ответил на запрос каталога. В отчёте запуска указано количество прочитанных карточек — до пяти. Нулевой результат означает, что API вернул пустой каталог.

Красная отметка означает, что один из шагов не завершился. Откройте задание и красный шаг:

- Сообщение о недоступном секрете: проверьте, что `EMALL_API_TOKEN` добавлен именно в **Secrets and variables → Actions** нужного репозитория.
- HTTP 401: Emall не принял ключ. Проверьте рабочий ключ в секретах репозитория.
- HTTP 403: Emall отказал в доступе. Проверьте роль и права ключа на чтение каталога.
- Сетевая ошибка или ошибка схемы ответа: сохраните текст сообщения для разбора. Тело ответа и ключ в журнал не выводятся.

В журнал и отчёт попадают только статус и общие количества. Названия товаров, артикулы, цены, остатки и полные ответы каталога эта проверка в публичных логах не размещает. Артефакты с каталогом не создаются.

## Что уже делает эта проверка

Workflow использует Node.js 24.19.0, запускает тесты клиента на искусственных данных и затем выполняет только чтение рабочего API: `GET /open/api/v1/products?page=1&perPage=5`. Ключ доступен только шагу чтения; репозиторию выданы права `contents: read`.

Команда — `node scripts/check-emall.mjs --summary`. Карточки HomeHarmony она пока не создаёт, фото не загружает, цены и остатки не изменяет. Реальный перенос первых пяти товаров остаётся следующим этапом после успешной проверки доступа.

Работающий магазин с Node.js, SQLite, заказами и админкой потребует отдельного размещения. GitHub Pages может показывать статический просмотр, а сервер приложения там не запускается. Размещение магазина можно сделать позже.
