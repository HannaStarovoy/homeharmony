# Массовый перенос Emall

## Готовый пакет

[Успешный массовый запуск](https://github.com/HannaStarovoy/homeharmony/actions/runs/41817572392): получено 145 товаров, подготовлено 144 карточки и 343 фотографии. Один товар `9366857` пропущен с `NO_VALID_PHOTOS`: корректных фотографий нет в полученных ответах списка и полной карточки.

После применения пакета в рабочей копии: 139 новых черновиков и 5 ранее опубликованных товаров Emall. Их публикация сохранена; остальные 14 демонстрационных товаров не менялись. Применение и повторный запуск проверены, в админке проверено открытие карточки. Пройдены 164 серверных теста.

[Посмотреть импортированные черновики](../preview_emall_mass.png).

Команда читает весь каталог по страницам (до 5000 товаров), скачивает фотографии и создаёт проверенный пакет. Новые карточки становятся черновиками. Повторный перенос сохраняет внешние связи, статус публикации и местные остатки; дубли не создаются. Ошибки категории, цены, количества и фотографий записываются в `review.json`, остальные карточки продолжают обрабатываться. Нераспознанные категории не назначаются произвольно.

## Обновить магазин на компьютере

Остановите магазин через Ctrl+C. Скачайте свежий ZIP репозитория и скопируйте содержимое `homeharmony-main` в вашу существующую папку магазина, заменяя файлы кода. **Существующую папку `var` не удаляйте и не заменяйте**: там ваши товары, вход в админку и заказы. Команды выполняйте в папке с обновлённым `package.json`.

## Через GitHub

1. Для уже готового пакета откройте [успешный запуск](https://github.com/HannaStarovoy/homeharmony/actions/runs/41817572392). Чтобы получить свежие данные, откройте Actions → **Массовый импорт Emall** → Run workflow. Используется уже сохранённый EMALL_API_TOKEN.
2. В блоке Artifacts скачайте **emall-all**. Распакуйте его в папку `emall-all` внутри вашего проекта. Проверьте: файл должен находиться по пути `homeharmony-main\emall-all\manifest.json`, рядом — `review.json` и папка `media`.
3. Остановите магазин: Ctrl+C в окне, где запущен `npm start`.
4. Из папки магазина выполните:

```text
npm run emall:apply -- .\emall-all
npm start
```

Команда проверяет пакет, сохраняет резервную копию SQLite в `var/backups`, переносит файлы в `data/emall-mass` и применяет записи. Рабочую папку `var` не удаляйте. В админке выберите «Черновики» и проверьте новые товары. Первые пять ранее опубликованных товаров сохраняют свой статус.

В `review.json` раздел `skipped` показывает ID и причины пропусков. Для неизвестной категории указан путь Emall: соответствие добавляется в `data/emall-category-map.json` и импорт запускается снова. Исправленный товар попадёт в следующую загрузку. Названия, описание, цены и фотографии существующих связанных товаров при изменении пакета могут обновиться; местные остатки сохраняются.

Пакет в GitHub хранится семь дней. Рабочая база компьютера не передаётся GitHub. Пакет содержит данные каталога и фотографии, без ключа API, заказов и покупателей. Сам запуск workflow не меняет магазин на компьютере — нужен шаг применения.

## Для разработчика

```text
npm run emall:import
```

Требуется `EMALL_API_TOKEN` в окружении процесса. Результат — `var/emall-all`; существующая папка не перезаписывается. Можно задать `-- --output другой-путь`. Неполная выборка при превышении лимита отклоняется. Пакет ограничен 512 МБ нормализованных фотографий. Непрерывная синхронизация остатков не включается.

Для повторной обработки пропусков можно указать номер предыдущего успешного запуска в поле `resume_run_id` при запуске workflow. Уже подготовленные карточки и фотографии берутся из его артефакта; пропущенные товары проверяются снова. Для полного обновления цен и описаний оставьте поле пустым. Если фотографии списка недоступны, импорт дополнительно проверяет полную карточку того же товара.

Для повторной браузерной проверки установленного массового пакета: `node scripts/capture-emall-mass.cjs`. Проверка использует временную базу и не меняет рабочие карточки.
