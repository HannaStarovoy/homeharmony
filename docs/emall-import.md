# Подключение Emall: статус и следующий шаг

## Что работает

Чтение рабочего API подтверждено [успешной проверкой GitHub Actions](https://github.com/HannaStarovoy/homeharmony/actions/runs/41725736609), а подготовка карточек — [успешным запуском импорта](https://github.com/HannaStarovoy/homeharmony/actions/runs/41797701461). Первые пять настоящих товаров преобразованы в формат HomeHarmony; [пакет с 13 фотографиями](../data/emall-drafts/manifest.json) сохранён в репозитории. По указанию владельца эти пять карточек [опубликованы в каталоге приложения](emall-publication.md). При обычном `npm start` новая установка загружает карточки и однократно применяет решение о публикации. Остальной каталог не переносился.

[Состав пяти карточек, предупреждения и проверка в админке](emall-drafts.md). У двух шапок пропущены недоступные исходные обложки и выбраны другие рабочие фото. Четыре значения характеристик восстановлены по согласованным ID в справочниках выбранных категорий, шесть значений пропущены с предупреждением. [Повторная сверка](emall-review.md) подтвердила остатки и выявила обновлённые цены двух товаров. Данные карточек и фотографии размещены в публичном репозитории с разрешения владельца; ключ, учётные записи и заказы в пакет не входят.

Документация не уточняет, включает ли `stock` резервы Emall; при управлении остатками нужна сверка с кабинетом продавца. Непрерывной синхронизации остатков между каналами пока нет. Неизвестные категории остального каталога потребуют отдельного сопоставления; [массовый импорт доступен отдельным workflow](emall-mass-import.md).

## API и запуск через GitHub

Документация, предоставленная владельцем: https://api-sandbox.emall.by/docs. Рабочий адрес — `https://api.emall.by`, тестовый — `https://api-sandbox.emall.by`. Клиент использует `Authorization: Bearer …` и `Accept: application/json`.

Для работы через GitHub настраивать облачную среду ChatGPT не требуется. `EMALL_API_TOKEN` хранится в Secrets репозитория и передаётся только шагу чтения рабочего API. Ключ не записывается в исходники, аргументы процесса, пакет или журнал. Сетевой клиент передаёт заголовок curl через stdin, наследует настройки прокси и TLS, не выполняет редиректы API и не выводит тела ошибок. Фото скачиваются отдельно без этого заголовка.

Доступны два ручных workflow:

- [Проверка чтения API](emall-github.md) запрашивает до пяти карточек и выводит безопасную сводку. Она не создаёт карточки, не загружает фотографии и не отправляет изменений в Emall.
- [Подготовка пяти черновиков](../.github/workflows/emall-import.yml) читает данные и справочники, загружает фотографии, проверяет пакет во временной базе и сохраняет его как артефакт. Workflow не меняет рабочую базу магазина; проверенный пакет применяется после сохранения в `data/emall-drafts/` и запуска магазина.

## Чтение и преобразование

Проверка чтения из терминала разработчика:

```bash
node --env-file-if-exists=.env.local scripts/check-emall.mjs --summary
```

По умолчанию клиент запрашивает максимум пять товаров через `GET /open/api/v1/products?page=1&perPage=5`. Флаг `--summary` скрывает данные карточек. Без него результат содержит ID, названия и исходные поля проверки; `imported` всегда равен нулю. `priceCents` — цена в копейках, `stockReportedByEmall` — количество источника без утверждения об учёте резервов. Для sandbox используются отдельный `EMALL_SANDBOX_API_TOKEN` и флаг `--sandbox`; рабочий ключ туда не передаётся.

`server/emall.mjs` проверяет пагинацию `data`/`meta`, повторяющиеся ID и целостность ответа. При несовпадении формата диагностика содержит только известный путь поля и его тип, без значений и неизвестных ключей ответа.

`server/emall-adapter.mjs` переводит цены в BYN, сопоставляет категории и расшифровывает свойства по справочникам. Отсутствующие цена или количество не превращаются в ноль. Для новых карточек нужна подтверждённая категория; явные соответствия находятся в `data/emall-category-map.json`. Нерасшифрованное свойство пропускается с предупреждением. Старая цена, не превышающая текущую, сбрасывается. Один ID Emall создаёт один товар и SKU: схема списка не содержит надёжной группы вариантов, поэтому одинаковые названия не объединяются.

`server/emall-media.mjs` загружает фотографии только с подтверждённых HTTPS-хостов, проверяет каждый редирект, тип, размер и возможность декодирования, затем сохраняет локальный WebP. В подготовке пакета недоступное изображение можно пропустить с предупреждением, но у товара должна остаться хотя бы одна корректная фотография. Небезопасные URL и ошибки записи останавливают подготовку. Заглушки не создаются.

## Применение пакета и защита данных магазина

`server/draft-bundle.mjs` проверяет формат, хеши и файлы фотографий до импорта. Обычный запуск магазина загружает `data/emall-drafts/`; сохранённая версия пакета защищает ручные правки от повторного применения при перезапуске. Недостающий файл фотографии восстанавливается из пакета без перезаписи карточки.

`server/imports.mjs` применяет нормализованные записи в общей транзакции:

- Новые карточки создаются черновиками. Существующие пользователи, заказы и товары сохраняются.
- Связь строится по источнику, среде, постоянному ID каталога продавца, внешнему ID товара и ID варианта. Для этого каталога используется `homeharmony-emall-main`, не API-ключ и не его хеш. Одного совпадения артикула для перезаписи недостаточно.
- Исходный артикул хранится отдельно; локальный SKU определяется связью источника. Повторный перенос сохраняет ID и SKU. Связанные артикулы защищены от случайного переименования и удаления.
- Sandbox и production разделены. Тестовую карточку нельзя опубликовать в рабочей витрине.
- Новый пакет может обновить название, описание, характеристики и цены. Локальная категория и состояние публикации существующего товара сохраняются. Дополнительные локальные характеристики и отсутствующие в выборке варианты не удаляются автоматически.
- Остаток копируется при создании нового SKU. Повторный импорт сохраняет локальное количество и выдаёт `LOCAL_STOCK_PRESERVED`, чтобы внешний снимок не восстанавливал уже проданные на сайте единицы. Это не заменяет синхронизацию каналов.
- Связи, товары, журнал партии и отметка версии пакета сохраняются атомарно. Ошибка откатывает партию.

Неизменённый пакет не перезаписывает ручные правки. При применении новой версии ручные фотографии пока не защищены от замены ссылок на фотографии источника. Перед публикацией нужны проверка карточки и сверка доступного количества.

## Внутренний формат для разработки

Следующий пример искусственный, **это не ответ Emall API**. Такой формат принимает ядро импорта после преобразования данных адаптером.

```json
{
  "source": {
    "provider": "emall",
    "environment": "sandbox",
    "account": "test-account-not-real"
  },
  "products": [{
    "externalId": "test-product-1",
    "name": "Искусственный пример для теста",
    "cat": "beanies",
    "summary": "Тестовый текст, не карточка Emall.",
    "attrs": {"Материал": "Тестовый материал"},
    "images": [],
    "variants": [{
      "externalId": "test-variant-1",
      "externalSku": "TEST-ARTICLE-1",
      "options": {"Цвет": "Чёрный"},
      "price": 12.5,
      "old": 0,
      "stock": 3,
      "images": []
    }]
  }]
}
```

`cat` — существующий ID категории HomeHarmony. Цены — числа в BYN с точностью до копеек. `stock` обязателен; `images` принимает только уже загруженные и зарегистрированные локальные фотографии.

Проверка нормализованного файла без сохранения:

```bash
node scripts/import-normalized.mjs --file prepared.json
```

Применение файла во внутреннем формате:

```bash
node scripts/import-normalized.mjs --file prepared.json --limit 5 --apply
```

Это отдельный инструмент разработчика. Для подготовки пакета непосредственно из Emall используется `node scripts/prepare-emall-drafts.mjs` в процессе с настроенным ключом; подробности в [инструкции о пяти черновиках](emall-drafts.md).

Серверные `npm test` используют искусственные ответы и временные базы: проверяют преобразование, безопасность фотографий, отсутствие дублей, разделение сред и продавцов, атомарность, сохранение резервов и снимков заказов. Реальный пакет дополнительно проверяется во временной базе и через `node scripts/capture-emall-drafts.cjs`: пять черновиков, цены и фотографии, отсутствие публикаций, сохранение идентификаторов после перезапуска.
