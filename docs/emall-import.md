# Подключение Emall: статус и следующий шаг

## Что пока не подключено

Ссылка, предоставленная владельцем проекта: https://api-sandbox.emall.by/docs.

**Основной путь без настройки облачной среды ChatGPT — [запуск проверки через GitHub Actions](emall-github.md).** Ключ сохраняется в Secrets репозитория GitHub. Запуск вручную читает до 5 карточек и выводит только безопасную сводку; данных каталога и ключа в отчёте нет.

Это адрес тестовой среды. Ранее прокси блокировал запросы (`CONNECT tunnel failed, response 403`), затем документация открылась с HTTP 200. По ней подтверждены рабочий адрес `https://api.emall.by`, тестовый `https://api-sandbox.emall.by`, заголовки `Authorization: Bearer …` и `Accept: application/json`.

Для дополнительного пути из облачной машины в черновике её настроек подготовлен HTTP-секрет `EMALL_API_TOKEN`, назначенный только для `api.emall.by`; при последней проверке его сохранённая привязка и переменная отсутствовали. Это не мешает запуску через GitHub: там используется отдельный секрет репозитория. Значения ключей не читаются из чата и не записываются в исходники, аргументы команд или журнал.

**Чтение рабочего API с настоящим ключом проверено:** [успешный запуск GitHub Actions](https://github.com/HannaStarovoy/homeharmony/actions/runs/41725736609) получил 5 настоящих карточек за одну страницу. В безопасной сводке подтверждены `received: 5`, `pagesRead: 1`, `imported: 0`. Сами данные карточек и ключ в журнал не выводились. Импорт этих товаров на сайт и загрузка всего каталога ещё не выполнялись.

Текущие настройки среды разрешают доступ в интернет. Это не подтверждает успешную публикацию среды: интерфейс отдельно сообщал об ошибке публикации, причина которой не предоставлена в доступной диагностике. Сохранение черновика конфигурации, получение HTTP 200 от документации и публикация среды — разные операции. Секреты вводятся только в защищённые настройки, не в чат, Git или командную строку.

Для реального переноса остаётся:

1. Сверить выбранные первые 5 карточек с нужным каталогом продавца; передача данных из API в локальную модель магазина ещё требует реализации.
2. Определить постоянный идентификатор каталога продавца и соответствие категорий, не зависящие от ротации API-ключа.
3. Довести преобразование карточек, фотографии, цены и остатки; определить, что означает количество Emall — физический или доступный остаток.
4. Полученные карточки преобразовать во внутренний формат ниже; согласовать соответствие категорий четырём разделам HomeHarmony. Фотографии скачивать только с подтверждённых HTTPS-хостов Emall/CDN и обрабатывать существующим сервисом изображений. Ключ API не должен уходить на адреса фотографий.
5. Прочитать и проверить 5 товаров, создать черновики и сравнить название, описание, фото, варианты, цену и наличие с источником. Только после этой проверки выполнять перенос остального каталога.

Доступ к тестовому API не доказывает доступ к рабочему каталогу. Разрешение на чтение рабочего API не распространяет ключ на адреса фотографий.

## Проверка чтения API

```bash
node --env-file-if-exists=.env.local scripts/check-emall.mjs
```

Команда по умолчанию запрашивает максимум 5 товаров через документированный `GET /open/api/v1/products?page=1&perPage=5`. Она не создаёт и не обновляет карточки HomeHarmony, не загружает фото и не отправляет изменений в Emall. Для sandbox используется отдельный `EMALL_SANDBOX_API_TOKEN` и флаг `--sandbox`; рабочий ключ туда не передаётся.

Клиент учитывает `data` и `meta` пагинации, проверяет повторяющиеся ID и целостность ответа. Сетевой запрос использует установленный curl с унаследованными прокси и TLS-настройками. Ключ передаётся curl через stdin, не через аргументы процесса. Редиректы не выполняются. Ошибки не выводят тела ответов и заголовок авторизации.

Результат содержит число прочитанных карточек, ID, названия и исходные поля проверки; `imported` всегда равен нулю. `priceCents` — цена в копейках (например, 2000 означает 20 BYN), `stockReportedByEmall` — количество источника без утверждения об учёте резервов. Отсутствующее поле не превращается в нулевой остаток или цену.

Официальная схема списка не содержит надёжного ID группы вариантов. Нельзя объединять товары по совпадению названий. Числовые характеристики `properties` требуют расшифровки через справочники, а категории Emall — соответствия локальным категориям. Фото из `images` ещё нужно отдельно скачать и зарегистрировать в локальном сервисе изображений без передачи ключа на хосты фотографий. Для связи каталога продавца нужен постоянный локальный идентификатор, не сам API-ключ и не его хеш.

Тесты сетевого клиента подставляют искусственные ответы. Они проверяют пагинацию, совместимость форматов, ошибки и защиту ключа, но не подтверждают авторизацию или доступность реального каталога. При несовпадении формата клиент сообщает только известный путь поля и его тип; значения и неизвестные ключи ответа не попадают в диагностику.

## Что реализовано локально

`server/imports.mjs` — подготовленное ядро импорта, **не HTTP-клиент Emall**. Оно принимает нормализованные записи от будущего адаптера.

- По умолчанию выбирает только первые 5 товаров, все их варианты сохраняет вместе.
- Предварительная проверка не создаёт импортируемые товары. Новые карточки создаются черновиками.
- Связь строится по источнику, среде, каталогу продавца, внешнему ID товара и ID варианта. Одного совпадения артикула для перезаписи существующего товара недостаточно.
- Исходный артикул хранится отдельно и отображается в админке/карточке. Локальный артикул детерминированный, чтобы одинаковые исходные артикулы разных каталогов не сталкивались. Повторный перенос сохраняет локальные ID и SKU.
- Sandbox и production разделены. Тестовую карточку нельзя опубликовать в рабочей витрине.
- Повторный запуск обновляет названия, описание, характеристики и цены; локальная категория и состояние публикации существующего товара сохраняются. Неизменённые карточки не переписываются.
- Локальные дополнительные характеристики и варианты, отсутствующие в полученной выборке, не удаляются автоматически.
- Физические остатки копируются при создании нового SKU. Повторный запуск сохраняет локальные остатки и выдаёт предупреждение `LOCAL_STOCK_PRESERVED`: это предотвращает восстановление уже проданных на сайте единиц из несинхронизированного внешнего снимка. Непрерывная синхронизация остатков между каналами ещё не реализована.
- Создание/обновление карточек, связей и журнала партии выполняется в общей транзакции. Ошибка откатывает всю партию, не оставляя товара без связи.
- При отсутствии фотографий выдаётся `NO_LOCAL_PHOTOS`; код не утверждает, что фотографии получены. Неизвестные категории, отсутствующие цены/количества, дубли внешних ID и неподтверждённые фото-ссылки приводят к отказу.

Миграция №3 создаёт `import_products`, `import_variants`, `import_runs`, сохраняя существующие товары и заказы. Связанные артикулы защищены от случайного переименования/удаления.

## Внутренний формат для разработки

Следующий пример — искусственный, **это не ответ Emall API**. В рабочем сценарии его сформирует адаптер после чтения документации.

```json
{
  "source": {
    "provider": "emall",
    "environment": "sandbox",
    "account": "test-account-not-real"
  },
  "products": [{
    "externalId": "test-product-1",
    "name": "Искусственный пример для теста",
    "cat": "beanies",
    "summary": "Тестовый текст, не карточка Emall.",
    "attrs": {"Материал": "Тестовый материал"},
    "images": [],
    "variants": [{
      "externalId": "test-variant-1",
      "externalSku": "TEST-ARTICLE-1",
      "options": {"Цвет": "Чёрный"},
      "price": 12.5,
      "old": 0,
      "stock": 3,
      "images": []
    }]
  }]
}
```

`cat` — существующий ID категории HomeHarmony. Цены — числа в BYN с точностью до копеек. `stock` обязателен; отсутствующее значение не превращается в нулевой остаток. `images` здесь принимает только уже загруженные и зарегистрированные локальные фотографии; скачивание из Emall ещё не реализовано.

Разработчик может проверить подготовленный нормализованный файл локально:

```bash
node scripts/import-normalized.mjs --file prepared.json
```

Сохранение выполняется только с явным `--apply`. Это внутренний инструмент, а не команда подключения к Emall:

```bash
node scripts/import-normalized.mjs --file prepared.json --limit 5 --apply
```

Проверки `npm test` используют искусственные записи и временные базы: отсутствие дублей, разделение сред/продавцов, атомарность после ошибки, сохранение резервов и снимков заказов, обновление исходных артикулов, защита связанных SKU. Они не подтверждают работу Emall API.
